# 会社PC 引き継ぎ書（PDF解析・OCRアプリ）

自宅PC版でのOCR基礎機能（JBig2 PDF対応、文字座標取得、画像PDF判定など）の開発が完了し、「第1完成」状態となりました。
この引き継ぎ書は、会社PCで同等の開発環境を構築し、次の開発ステップ（帳票フォーマット登録や部分OCRなど）へ進むための手順をまとめたものです。

## 1. 環境要件
- **Node.js**: v20以上推奨（自宅環境に合わせてください）
- **npm**: v10以上
- **Git**: 最新版

## 2. 起動手順

会社PCにて、以下の手順でアプリを起動してください。

1. **GitHubからコードを取得する**
   お使いのGitクライアント（またはコマンドライン）を使用して、対象リポジトリを `git clone` します。
   ```bash
   git clone <リポジトリのURL>
   ```

2. **プロジェクトフォルダを開く**
   VS Code などのエディタで、クローンした `pdf-ocr-verification` フォルダを開きます。

3. **PowerShell（ターミナル）を開く**
   エディタ内蔵のターミナル（Ctrl + ` 等）を開き、PowerShellが選択されていることを確認します。

4. **プロジェクトフォルダへ移動する**
   ターミナル上で、カレントディレクトリが `pdf-ocr-verification` になっていることを確認してください。
   ```bash
   cd path/to/pdf-ocr-verification
   ```

5. **依存パッケージをインストールする**
   以下のコマンドを実行し、必要なパッケージ（`pdfjs-dist`、`tesseract.js` など）をインストールします。
   ```bash
   npm install
   ```

6. **環境変数ファイル（.env.local）を作成する**
   `.env.example` の内容をコピーし、`.env.local` という名前のファイルを作成してください。必要に応じて、Google Apps Script API の URL 等を設定します。（OCR基本動作のみであれば設定なしでも起動可能です）

7. **開発サーバーを起動する**
   以下のコマンドを実行します。
   ```bash
   npm run dev -- --webpack
   ```

8. **起動完了を確認する**
   ターミナルに `Ready in XXXXms` が表示されたら起動成功です。

9. **ブラウザで開く**
   ブラウザを立ち上げ、以下のURLにアクセスします。
   [http://localhost:3000](http://localhost:3000)

10. **テストPDFを読み込む**
    画面の「Upload PDF」ボタンなどからテスト用のPDFを読み込み、動作を確認してください。

---

## 3. 最初に確認するテスト

会社PCの環境構築後、以下の4点を最初にテストしてください。

**A. 通常文字PDF**
- **確認内容**: OCRなしで文字枠が青く表示され、直接文字取得ができていること。

**B. 画像PDF**
- **確認内容**: 画像PDFとして判定され、OCR準備 → OCR実行ボタンが押せること。実行後に青枠が表示されること。

**C. JBig2問題PDF（今回解決したPDF）**
- **確認内容**: 白紙にならず正常にCanvas上に表示されること。

**D. 実際の会社帳票**
- **確認内容**: 会社の実業務で使われるPDFを読み込み、現状のOCRでどこまで正確に文字抽出できるかを確認すること。

---

## 4. 次の開発テーマ（会社PCでの予定）

自宅PC版での基盤構築は完了したため、今後は会社の実帳票を用いた実践的な開発へ移行します。

- **第1優先**: 帳票フォーマット登録（帳票の種類の特定、読む場所・無視する場所の設定）
- **第2優先**: 読み取り範囲指定（店舗名、数量、合計などの項目定義）
- **第3優先**: 項目単位OCR（全文ではなく、必要な指定範囲のみOCRを実行し処理を高速化・高精度化）
- **第4優先**: 信頼度判定（高信頼度は自動OK、低信頼度は要確認とするロジック）
- **第5優先**: 人による確認・訂正UI（怪しい箇所を色付けし、手動修正・承認できる仕組み）
- **第6優先**: 帳票ルール保存（同一フォーマットの次回自動認識）

※文字抽出精度のAI補正や複数ページ一括処理などの応用機能は、実帳票ベースの調整が済んだ後に行います。
